FIRST MODULE / HOST CONTRACT
Implement an isolated sparse process-owned backing model plus mapping PLAN,
not real page-table activation or an independent allocator. Platform supplies
caller-owned metadata storage and backing through a callback interface. Agree
this minimal prototype shape (prefix all exports x64_pm_):
  X64PmBacking { uint64_t id; uint8_t *bytes; }
  X64PmOps { void *opaque;
    int (*alloc4k)(void *, X64PmBacking *out);
    void (*free4k)(void *, X64PmBacking backing); }
Success alloc4k returns one exclusive zeroed4096-byte aligned payload with a
nonzero4096-aligned unique id; failure returns0 without transferring ownership.
A host fixture id is a validated handle, not a physical address to dereference.
bytes is the backend's valid kernel/host alias for that allocation and may
numerically differ from id. Keep metadata/refcounts OUTSIDE the4096 payload.
The model owns each successful allocation until exactly one free4k; no caller
retains a borrowed payload pointer across mutation/release. Backend is the
only allocator; do not call page_alloc/page_free, mmap/mprotect, CR3/invlpg,
PCI/DMA/MMIO, IRQ or scheduler code inside the module. Production kernel adapter
will validate physical frames/aliases and budget against the real allocator.

Initial logical model remains BANK64000 cells, uint16 cells, bounded256 banks.
Private [0,240*64000) cells is30,720,000 bytes =7500 hardware4K payloads.
Shared [240*64000,256*64000) cells is2,048,000 bytes =500 hardware4K payloads;
mark this as a separate platform-owned region, not private clone/free content.
Existing1024-cell snapshots are2KiB; RamPage adds a refcount before cells and
cannot be installed as a raw4K data PTE. A4K payload spans2048 flattened cells,
possibly crossing a64000-cell bank boundary. Always translate validated logical
bank/offset to flattened cell index first; numeric logical pointers are NOT
native virtual offsets. Keep first32 logical-cell MMIO effects in checked
helpers; backing there is not permission for direct device access. No chosen
ring-3 VA, public Context offsets, permissions or shared-kernel user mapping
are approved by this prototype contract.

Provide create/zero/read/write/clone/release and bounded mapping-plan query
operations with explicit errors, checked spans and stable backing identity.
A query/selection emits or selects owned frame references; it copies no payload,
installs no live mapping and never changes a run queue. Start with eager sparse
clone as a simple correctness baseline; COW is a later explicit extension, not
required here. Preserve holes as zero, cross-page/bank widths and all16 cell
bits. Failed operations (including failed clone/allocation) leave existing
spaces/content/ownership unchanged and release all staged allocations. API/name
and metadata-size details may evolve inside this isolated subtree; publish the
header/design/results here for review before any production adapter depends
on them. Do not imply these prototype callbacks settle the production PTE/
TLB/address-space ABI. That requires another exact interface review.

Concrete fast-memory sketch FOR REVIEW, not an agreed ABI
~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~
Start read-only. A capability-enabled compiler may call an explicitly versioned
internal helper, tentatively:
  rcc_native_memview_v1(ctx, logical_hint, cell_count, requested_flags)
The existing private helper ABI carries/returns u64 values. The returned value
is zero (denied) or a host pointer to this explicitly specified C-compatible
record of FIVE u64 fields, in this order:
  version, flags, dense_start_cell, cell_count, host_base
host_base addresses the first uint16_t of that contiguous granted span. This
record is a new interface, never an assumed prefix/offset into Runtime/Context.
The compiler copies its fields into internal native SSA values immediately;
neither that record pointer nor host_base can enter guest IR-visible storage,
arguments, function tokens, continuation slots or process snapshots.

For v1, only READ grants are usable. Runtime may deny ANY request. Denial, an
unsupported version, insufficient permission, a range miss, bank/page crossing,
volatile access or bank-zero device memory selects the old checked operation.
Shared kernel storage is initially denied because its mutex/synchronization
must not be bypassed. X64 can grant an eligible flat private span; hosted can
grant a stable private backing page. No write grant or eager COW detachment is
required. A future write capability must separately specify dirty tracking and
hosted COW ownership; it cannot be inferred from a nonnull host_base.

Acquire/cache once for a useful proven-safe access region, not unconditionally
per scalar operation. Cached views die on suspension/resume, switch, fork,
exec, backing growth/remap, COW detachment, and every call without a reviewed
non-invalidating contract (including checked stores/copy/fill). Reacquire after
those barriers. Initially retain checked code if the compiler cannot establish
a useful safe lifetime. Preserve the aggregate-return checkpoint guard.

Polling remains an OPEN interface obligation: checked scalar helpers poll even
when no scheduling checkpoint is due. Fast lowering must preserve those
opportunities/cadence. Neither silently dropping per-access polls nor assuming
a polling helper cannot invalidate a view is accepted. Runtime owners should
review this explicitly before scalar fast paths are emitted.

Emission must be opt-in via an explicit native codegen/build capability, off by
default. With it off, do not import even the new acquisition/capability helper.
Keep required-helper manifests/cache identities explicit. Enabling a profile
must not accidentally enable fast-memory imports in the freestanding runtime.
The exact option name/helper record and polling contract await review.
