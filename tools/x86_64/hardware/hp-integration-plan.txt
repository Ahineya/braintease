Physical baseline at that planning snapshot:
- Fast GOP console, NVMe persistence, offline apps, combined default USB boot,
  service supervision, pkg installation and SSH/SFTP/Telnet have worked on HP.
  Dedicated p3 reserves 30 GiB; the current C16 V3 filesystem uses 1 GiB.
- Orderly reboot is physically confirmed. Shutdown syncs and stops; ACPI S5
  power-off, suspend/resume and general laptop power management are pending.
- Userland wifid controls retry/backoff and pause/reconnect. Native firmware,
  association and key handling remain privileged; the test profile is embedded.
  This is not yet a userland supplicant or saved-profile network selector.
- Current EFI 502111b00b958e189ffdad168a9184cd9e3d61f2c0cfc24468ba85fac5c3f8c6
  has ordinary GTK-refresh support. A 602-second single SSH process and binary
  SFTP round trip passed without reassociation. A later periodic check recorded
  GTK refreshes=1, generation=1, attempts=1 and no duplicates/rejections. A held
  SSH session across an actual rotation remains OPEN. Fresh pairwise handshake
  requests still use the explicit reconnect fallback. Do not call all rekeys
  seamless or interpret periodic SSH snapshots as continuous-session proof.
- Native instructions still use C16 layouts/private calls and checkpoint
  scheduling at ring 0 on one CPU. The isolated process-memory prototype is
  host-tested, not installed PTEs, ring 3, timer preemption or SMP.
- RVM/Fuse-X GUI, input, audio and application acceptance is reusable work,
  not proof of a bare-metal HP backend. Keep target identities separate.

Suggested sequence, with independent lanes running alongside it:

1. Finish the reliable remote development loop.
   Observe a real GTK rotation with the association and a held session intact;
   test sustained traffic, idle operation, reconnect fallback and manual pause.
   Keep local console independent of network/service failure. Stage kernel/EFI
   updates separately from application packages, retaining a known-good image.
   Wi-Fi profiles and DHCP integration can proceed above the driver boundary;
   shared DHCP work elsewhere is not automatically connected to HP eth0.

   Internal EFI installation can follow this baseline without waiting for GUI,
   LP64, a new filesystem or every app. Keep Ubuntu and USB recovery, create an
   independent Riplix EFI path/entry, trial a one-shot boot, then set the default
   after physical acceptance. For unattended remote kernel updates add verified
   candidate publication, health confirmation and a real failed-boot recovery
   mechanism. Merely changing BootOrder/BootNext does not recover a hung kernel.
   Implement and verify ESP access/update tooling; current EFI embeds kernel.

2. Make the existing console a dependable application platform.
   Fix Escape, extended arrows, Home/End/Insert/Delete/Page keys, F keys,
   independent modifiers and bounded multi-character input buffering. Emit the
   sequences understood by the shared terminal/curses stack. Fn may be handled
   entirely by firmware; inventory actual scan/ACPI events before promising a
   distinct Fn key. Media/lid/tablet events may need HP WMI/Intel HID/ACPI work.

   Report real console geometry via the terminal-size device contract, then
   verify TIOCGWINSZ, termios, ANSI cursor/erase/scroll behavior and restoration
   after exit/signals. input.c currently omits Escape and discards most extended
   keys; runtime.c lacks terminal-size command 11. These are concrete platform
   gaps, not evidence that a different shell is required. Check Levee's own
   geometry limits separately. Test physical console and remote PTYs separately.

   Bring mux first, then Commander/mc and Rift with matching C16 x64 SDK/bindings,
   resources, PTY/job-control behavior and package manifests. mux has no graphics
   dependency (docs/terminal-multiplexer.md). Add chat and Telegram after checking
   their target crypto/TLS/entropy/time/socket contracts, not just compilation.
   Telegram's existing host crypto device needs a bare-metal implementation;
   networking alone does not supply those operations. Music/wavplay follow PCM.
   Keep app catalogs with their current owner; install incrementally through pkg.

3. Start execution foundations now, in parallel with driver/app work.
   Follow docs/arch/native-x64.md, not the old heavier-apps-before-preemption
   milestone. Measure switch copies and scheduling gaps; integrate reviewed
   process-owned hardware backing/PTEs under current safe checkpoints first.
   Define allocator/mapping/rollback/TLB and borrowed-view lifetimes with the
   isolated process-memory owner before changing the production platform.
   Separate user-compatible helpers from privileged services, then establish
   ring-3 code/data/stack, saved CPU/FP contexts, fault containment and checked
   user copies. Next add timer-driven single-CPU userspace preemption while
   keeping initial kernel critical sections non-preemptible and bounded.
   Acceptance includes a syscall-free busy loop beside a responsive shell,
   fork/exec/signals, failed exec rollback and complete page reclamation.

   LP64 contract/SDK design may run alongside this, but is not a prerequisite
   for C16 isolation. Use explicit Riplix ABI-tagged static ELF64, System V AMD64
   calls, ordinary byte addressing/alignment and checked syscall adapters.
   ELF does not imply Linux binary compatibility. Freeze file-octet versus
   C16-cell semantics before mixed binary I/O. Use Clang as the first oracle;
   extend guest RCC/RFL targets afterward while retaining C16 compatibility.
   Guest compiler hosting, guest image construction and LP64 output are separate
   milestones. OS_BOOTSTRAP.md still records a host platform/loader capsule and
   pending complete in-guest image acceptance; do not call it fully self-hosted.

4. Grow hardware interaction and an early software-rendered desktop.
   Define one timestamped input/event contract with keyboard modifiers, pointer
   buttons/motion/wheel, focus and capture. Adapt it to terminal mouse reports
   and GX events, rather than letting apps read devices directly. Shared curses
   and mux already have xterm SGR mouse/reporting contracts to reuse.

   HP has i8042 keyboard but NO usable PS/2 AUX touchpad path. Its Synaptics
   SYNA32F6 touchpad is HID-over-I2C on Intel LPSS/DesignWare. External USB mice
   need xHCI + USB enumeration + HID; the built-in touchpad needs ACPI resource/
   interrupt discovery + I2C + HID descriptors. These are separate transports
   which should share HID/input decoding. Prioritize a practical pointer path,
   then reuse I2C/HID for ELAN2514 touchscreen/stylus later; gestures, calibration,
   rotation and tablet behavior have their own acceptance.

   Bring a bare-metal GX display/input backend and software composition over
   the existing GOP framebuffer. Reuse shared LVGL controls/themes and existing
   window/surface/event lifetime contracts; evaluate the Nano-X/FuseDE pieces
   against that common contract instead of creating incompatible GUI stacks.
   Fuse-X host windows and RVM desktop are not HP display backends. A small GUI
   prototype can proceed early; a responsive multi-app desktop needs execution
   isolation/preemption, correct input and bounded rendering/memory budgets.
   GPU acceleration is not a prerequisite for first windows or LVGL.

5. Add audio and fuller laptop power support as bounded hardware projects.
   Reuse docs/arch/audio.md's PCM configure/write/select/drain contract.
   HP's 8086:7e28 SOF/HDA path plus cs35l41 I2C amplifiers needs codec/DSP/
   firmware/topology investigation; a generic HDA driver is not proof of speaker
   output. Choose a verified first output path, add DMA/buffer ownership and
   underrun accounting, then test music/wavplay while network/UI work continues.

   Add real ACPI S5 power-off, battery/AC/lid/backlight and measured idle/thermal
   behavior. Suspend/resume is later cross-driver work: save/quiesce DMA, restore
   clocks/devices and reconnect networking safely. Reset already works; do not
   restart that milestone from scratch. Audio latency must be measured under
   contention; hard real-time scheduling is not implied by ordinary preemption.

   Bluetooth is USB 8087:0033, independent of AX211 Wi-Fi. Headphones require
   USB transport/HCI and firmware, discovery/bonding/security, an audio profile
   and codec/routing/buffering support. Sequence after basic USB and PCM; it is
   not merely another output switch on the Wi-Fi driver.

6. Build safer storage and advanced execution/display without blocking all apps.
   Investigate a replacement filesystem in parallel now; no format is selected.
   C16 V3 has 30-character names and no journal. Longer names change directory
   encoding, SDK limits, tools and recovery; changing NAME_MAX alone is invalid.
   Specify byte-oriented disk transport, VFS/mount dispatch, filename encoding,
   permissions/links, capacity limits and flush/ordering semantics first.
   Bring a new backend on disposable images/a separate test volume, validate
   malformed media and read-only access, then writes/crash recovery with injected
   power cuts and independent checking. Only promote it to root after migration,
   installer and recovery support pass. Journaling needs actual commit/barrier
   correctness; it is not supplied by a new block driver. It need not wait for
   LP64, but must share the explicit octet/C16 adaptation contract.

   Threads can begin on one CPU after execution/TLS/synchronization contracts;
   they do not require SMP. SMP follows stable single-CPU isolation/scheduling,
   kernel ownership/locking, per-CPU stacks/FP state, AP startup, TLB shootdowns
   and interrupt/device concurrency. HP has 12 cores / 14 logical CPUs. Avoid
   allowing every core into today's global runtime/kernel without that work.

   Split native Intel graphics into display/modesetting/backlight and rendering
   acceleration. HP is Meteor Lake 8086:7d45. Establish safe buffers/presentation,
   device memory and reset/fault ownership before command submission. Measure
   software composition first; add acceleration behind the same surface API.
   GPU and SMP are substantial projects, not prerequisites for a useful desktop.

Driver reuse and performance policy
-----------------------------------
Before each new hardware milestone, inspect Linux and OpenBSD sources for the
EXACT device/revision and firmware protocol, as requested by the user. Prefer
reusing well-bounded driver logic where its license and dependencies fit.
Record which source/version supplied structures and ordering. Porting still
needs Riplix PCI/ACPI, IRQ, DMA, timer, synchronization and error-recovery
adapters; do not create an unbounded Linux compatibility layer accidentally.
Imported structures are explicit wire/device layouts, not C16/native ABI guesses.

Keep a workload baseline: boot-to-local-shell and remote-ready time, input-to-
paint latency, frame damage/bytes copied, switch latency, CPU idle wakeups,
memory reclamation and audio underruns. Run an idle desktop and a busy app beside
SSH/storage/audio. Shared retained rendering already improved Commander/Rift;
native instruction execution alone did not remove avoidable application work.

  unavailable graphics/audio/crypto capabilities or mix hosted and HP objects.
- LP64 ABI probes/SDK/compiler work and filesystem format/VFS design can proceed

- Use small independent tests first, then one combined QEMU candidate and a
  physical hardware gate. Host prototypes and hosted app success do not satisfy
  ring-3, physical device, crash durability or uninterrupted rekey acceptance.
