Driver reference and native boundary
------------------------------------
Current OpenBSD if_iwx.c/if_iwxvar.h explicitly match MAC_TYPE_MA + RF_TYPE_GF
without CDB to iwx_cfg_ma_b0_gf_a0, with iwx-ma-b0-gf-a0-89 and its PNVM. This is
an exact-family starting reference beyond the generic AX211 marketing name.
Downloaded reference files retain notices and SHA256 provenance in sources.json.
The online iwx manual lists older firmware examples; source configuration is the
basis for the MA/API89 observation. This is NOT a completed portability review.

A native C/Clang platform driver can keep real64-bit BAR/DMA pointers outside
C16. The existing checked DEVICE_NET_INFO/TX/RX/STATS frame contract can remain
unchanged once Wi-Fi association produces a usable link. Radio control/scan/key
management needs a separate interface; do not overload raw-frame descriptors or
put credentials in diagnostic logs. Existing guest TCP/IP/sockets/PTYs are reused.

Work sequence / acceptance gates
--------------------------------
1. Read-only cold-boot PCI/CSR discovery: --wifi-probe. The optional probe does
   not size/rewrite BARs, enable memory decode, change power, reset, load firmware
   or start DMA. It skips an absent/wrong device, non-D0 state, disabled decode,
   malformed config or unavailable CSR. Native host tests prove no PCI/CSR writes;
   QEMU verifies absent-radio boot still reaches the normal working shell.
   Actual HP CSR acceptance is pending. This is discovery, not a Wi-Fi driver.
   Self-contained RAM-root production candidate (no NVMe access):
   build/x86_64-wifi-probe/normal/esp/EFI/BOOT/BOOTX64.EFI
   SHA256 4cf1b9f923233f11020cf06c9bccb2d177ccaf79c25e5637ba23884301320bd0
   Diagnostics reach the panel and serial. Exact production image passed the
   full QEMU shell/app/process/pipe/timer suite via USB. Candidate is NOT
   installed on USB; actual HP CSR acceptance remains pending.
2. Adapt the matching Intel transport: ownership/power/reset, bounded native DMA
   queues, checked TLV firmware + matching PNVM, firmware ALIVE and NVM/calibration.
   Preserve existing VT-d guards; do not disable an active IOMMU blindly. Keep
   buffers resident until the controller is actually quiescent. Poll initially
   if suitable; no guest execution from an ISR. Inspect all OpenBSD bus/task/
   net80211/crypto dependencies before choosing the reusable scope.
3. Scan APs with valid channel/regulatory information; verify SSID/security and
   signal against the known working recovery/Ubuntu results on this machine.
4. Managed association + WPA2-PSK/EAPOL/key installation; handle disconnect,
   retries, malformed management traffic and interface reset. No open-network
   substitute for the user's normal secured access point.
5. Bring up the existing IP stack (explicit initial IPv4 config is possible;
   DHCP and DNS configuration follow), then real HP ping and remote shell.
6. Curses UI using the existing guest library: scan list, signal/security,
   password entry with echo disabled, connect/disconnect/status and saved profiles
   protected by file mode0600. A small CLI/control boundary should serve both UI
   and initial setup from this chat. Ask for the password only when the secured
   association path can actually use it. No placeholder/fake scan results.
