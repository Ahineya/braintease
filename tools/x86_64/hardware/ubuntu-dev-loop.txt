Ubuntu SSH service
------------------
Repository sources:
  tools/x86_64/hardware/ubuntu-dev-ssh.sh
  tools/x86_64/hardware/ubuntu-dev-ssh.service

Installed on the HP as root-owned files:
  /usr/local/sbin/riplix-dev-ssh                 mode 0700
  /etc/systemd/system/riplix-dev-ssh.service    mode 0644

The existing /home/ahineya/temporary-root-ssh.sh is preserved. Its manually
started listener was handed over to the enabled, supervised systemd service.
The service starts after network.target and restarts after listener failure.

This deliberately retains the owner's requested passwordless root SSH on
192.168.100.107:2222: AuthenticationMethods=none, PermitRootLogin=yes,
PermitEmptyPasswords=yes, PasswordAuthentication=yes and UsePAM=no. It is
not a key-only login service. The SSH host key stays on the HP.

Before passwd -d root, the wrapper saves the original root password setting
only on the HP in /var/lib/riplix-dev-ssh/root-password.original, root-owned
mode 0600 inside a mode 0700 directory. Publication is atomic and both file
and directory are fsynced. An existing baseline survives an interrupted boot.
On a clean stop, the wrapper stops its listener, restores and syncs the
original setting, then unlinks and syncs the saved baseline. Secrets are
neither copied to the Mac nor printed in logs.

Boot and update loop
--------------------
1. Connect to Ubuntu root SSH on port 2222 using ssh.md. For a new EFI, follow
   efi-updates.md: verify disk/ESP identity, stage into a fresh namespace with
   internal_boot.py, and read back the new firmware entry. Do not try to update
   an existing namespace with the initial-staging tool.
2. To boot the already accepted GUI image, first verify live entry 0003 and its
   exact payload hash against the baseline. Then select it for one boot:

     efibootmgr -n 0003
     efibootmgr -v

   Require BootNext 0003 and Ubuntu-first BootOrder before deliberately running:

     systemctl reboot

   For a newly published candidate, use its independently read-back entry
   number instead; neither 0002 nor 0003 is a reusable allocation constant.
3. Reconnect to Riplix at 192.168.100.107:22 and run the acceptance checks.
   BootNext has been consumed; the persistent default remains Ubuntu.
4. In Riplix, run reboot. Ubuntu boots, and its SSH service on port 2222 returns
   automatically. Repeat from step 1 for the next candidate.

This is firmware one-shot selection, not automatic health rollback: a hung
Riplix candidate still needs a reset before Ubuntu can boot. Riplix does
not yet publish EFI updates or select Ubuntu through its own ESP writer.

Stop or remove the temporary listener
------------------------------------
From Ubuntu’s local console, stop it and prevent startup on later boots:

  systemctl disable --now riplix-dev-ssh.service

Stopping this service disconnects its SSH access. A successful stop reports
that the original root password setting was restored. A restore failure
retains the saved baseline for recovery; do not delete that baseline manually.
The original home-directory script remains available to its owner.

If removing the installed wrapper and unit as well, after a successful stop:

  rm /etc/systemd/system/riplix-dev-ssh.service
  rm /usr/local/sbin/riplix-dev-ssh
  systemctl daemon-reload

The temporary BootOrder is separate from service removal. Riplix-first
promotion is not part of this loop. If later requested, verify the live accepted
entry and construct the full desired order while retaining Ubuntu/recovery;
do not replay an old fixed BootOrder command. Latest accepted entry is recorded
as 0003, not the older terminal entry 0002. Entry0000 and
EFI/Riplix remain the previous accepted build. The older EFI's16MiB app limit
cannot run the current large Rift image; its retained shell/recovery role is
separate from rollback of installed applications.
