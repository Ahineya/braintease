Source-first queue and security review
--------------------------------------
Pinned OpenBSD if_iwx.c1.230 / if_iwxreg.h1.75, plus Linuxv6.12 iwl-trans.h,
fw/api/{rx,tx,mac}.h, mvm/rxmq.c and mac80211/wpa.c consumers were inspected.
Local URL/SHA records: build/x86_64-network/wifi-reference/live-wifi-sources.json,
protected-data-sources.json and earlier manifests. Michael uses OpenBSD
sys/crypto/michael.c1.2 with retained ISC notice and native unsigned octet loads.
Adaptation/SHA record: boot/wifi-crypto-sources.json. Notices accompany the EFI.

- Polled single-CPU NIC; no ISR runs guest code or changes scheduling.
- Permanent6MiB DMA pool; reusable256-slot native TX pages/TFH/byte-count ring.
  Hardware head/tail/SSN are16-bit counters; only native DMA indexing wraps
  at256. Ownership releases through bounded cumulative payload queue/SSN replies.
  Native copies never borrow C16 buffers. MAC sequence is12 bits, independent
  of the256-slot ring index. TX caps64 frames/64KiB, returning backpressure.
- Fixed-order512-buffer RX, one packet per buffer for AX210+ as iwx_rx_pkt does.
  Producer mask follows iwx_notif_intr. Refill publishes only processed buffers,
  aligned by8, with a64-buffer per-poll budget. Delivery caps64 frames/64KiB.
  No lifetime one-ring exhaustion remains in live mode; checkpoints retain it.
- Protected ToDS CCMP TX; firmware generates crypto IV/PN/MIC. RX requires the
  selected AP/channel, FromDS, valid hardware cipher/integrity/CRC, correct key
  index and increasing per-key/TID PN. No fragments/A-MSDU/HT/PMF are advertised.
- GTK CCMP/TKIP RX is supported. Gen2 TKIP requires ICV/MIC success; RADA bit26
  means firmware stripped ICV/Michael. Without RADA, trim indicated MAC trailer,
  verify retained Michael over DA/SA/priority/LLC with AP-to-STA GTK RX MIC key,
  and strip Michael/ICV. GTK replay floor starts at authenticated M3 RSC.
  Malformed/bad crypto never commits PN or output. Firmware integrity bits are
  actual consumer requirements; unknown status/padding bits stay opaque.
- Firmware/hardware/radio-kill errors, malformed ownership, a5s oldest-TX
  watchdog, changed country profile, AP disconnect or API4 beacon loss stop the
  interface. API4 missed-beacon layout is pinned and checked before startup.
  MIC failure and EAPOL retry/rekey after handoff also stop fail-closed.
  Automatic rekey/reconnect, full TKIP countermeasure recovery and user radio
  up/down/SSID selection are NOT implemented. Reboot reconnects with fresh nonce.
  ifconfig up/down currently controls the existing IP stack, not radio power.
